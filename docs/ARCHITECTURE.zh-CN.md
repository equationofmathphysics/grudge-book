# 仇恨之书多人版架构设计

版本 2 · 可独立部署源码版

适用对象：网站所有者、自托管部署者与后续维护者。

## 1 目标与部署边界

本版把单机小本本升级为按账户隔离的私密记录系统，增加双向好友和仅本人可见的被记仇总数。保留中文主题、个人别名、记录状态与刻碑体验；社交统计只处理明确授权的计数，不向好友发送标题、正文或个人别名。

### 两种部署共用业务规则

| 部署形态 | 身份来源 | 数据存放 |
| --- | --- | --- |
| 现有 Sites 托管版 | 平台登录和可信身份头 | Cloudflare Worker 与 D1 |
| 可迁移自托管版 | 本地用户名与密码 | Node.js 24 与 SQLite |

托管平台的访问范围由部署者独立配置。应用的账户隔离与好友功能不会自动改变站点访问权限；私有站点仍需维持原有访问控制。

### 不可忽略的产品约束

- 自托管账户不收集邮箱或手机号，不做邮件或短信验证，也没有密码找回和账户恢复流程。忘记凭据可能永久失去该账户入口。
- 好友必须双向同意；私人别名不能自动匹配真实账户。新账户不预置任何人的私人记录或指控。
- 聚合数字仅向被统计的本人展示。门槛和延迟只能降低推断风险，不能承诺匿名，也不能验证每个账号对应独立真人。

## 2 组件与信任边界

### 浏览器到业务层

浏览器加载静态页面、样式与脚本，通过同源 /api 请求访问业务服务。页面负责编辑、筛选、确认与错误提示；服务端负责认证、所有权、输入校验、好友关系和统计资格。前端隐藏按钮只是界面行为，不能作为权限依据。 私有 API 还校验 X-Grudge-Owner 与当前会话用户一致，阻止旧标签页在另一账号登录后误写入；这个头只是匹配校验，不能单独授予身份。

1. 读写小本本：已登录浏览器 → 身份适配层 → 账户所属 notebook → 返回本人记录和 revision。
2. 关联好友：本人持有对方主动提供的随机好友码 → 发起请求 → 对方接受 → 双向关系成立。
3. 查看汇总：本人请求统计 → 检查资格 → 读取或生成固定周期快照 → 仅返回本人汇总。

### 托管与自托管的适配

| 层次 | Sites 托管 | 独立服务器 |
| --- | --- | --- |
| 请求入口 | Worker 接收平台请求 | Node HTTP 服务与反向代理 |
| 认证 | 可信 oai-authenticated-user-id | 随机会话 Cookie 与数据库校验 |
| 业务逻辑 | 统一校验和授权规则 | 同一业务契约 |
| 数据库 | D1 绑定 | 本地持久化 SQLite 文件 |

托管认证头只能在平台可信入口中使用。独立部署不得直接信任外部客户端自报的同名头，也不能把它当作用户名密码登录的替代品。托管版本不叠加独立密码登录，以免破坏平台的身份边界。

### 保密边界

应用隔离的是不同普通账户之间的数据访问。服务器管理员与具备数据库访问权的运维人员仍可能读取原始数据。本版没有端到端加密，也没有应用层逐字段加密。HTTPS、磁盘加密、备份加密和受限运维权限属于上线配置要求，不能仅凭代码存在就宣称已经启用。

## 3 数据模型与一致性

账户、好友和安全事件使用关系表；每人的小本本是一行经过校验的 JSON，以 revision 防止整本覆盖。统计历史仅保存按目标账户的计数，不保存标题、正文或备注。

| 数据表 | 主键或唯一性 | 用途 |
| --- | --- | --- |
| members | id；平台身份、用户名、好友码分别唯一 | 身份适配、显示名和随机好友码 |
| notebooks | user_id | 本人 JSON、小本本版本号、更新时间 |
| entry_origins | user_id + entry_id | 保留原始关联，禁止删除后以同编号改关联 |
| sessions | token_hash | 自托管会话、用户 ID、有效期 |
| friendships | low_id + high_id | 一对用户一条关系，记录请求者和状态 |
| aliases | owner_id + friend_id | 单向私人备注，不互相共享 |
| rate_limits | bucket | 有截止时间的持久化计数桶 |
| aggregate_revisions | user_id + revision | 各版本计数投影与提交时间 |
| aggregate_snapshots | user_id + week | 本人周快照、资格和失效状态 |
| aggregate_revocations / privacy_state | user_id + week / id | 撤回锁定与并发快照版本保护 |
| auth_challenges / auth_failures | id / username | 一次性注册题摘要与账户失败锁定 |
| audit_grudges | id | 系统主体拥有的轻微安全事件 |

### 整本容量与字段约束

每账户最多 1000 条记录和 1000 位私人名册成员；规范化后的整本 JSON 不超过 1 MiB。记录 ID 最长 150 字符，对象最长 40 字符，标题最长 80 字符，正文最长 2000 字符。字段类型、日期格式、严重程度、类别、状态和重复 ID 均由服务端检查。废纸篓条目仍占容量。

version 表示 JSON 格式版本，revision 表示服务器并发版本，两者不能混用。写请求携带 expectedRevision；只有与当前 revision 相符时才提交并推进版本。导入走专门路径，不能通过备份文件指定自己的所有者。

### 索引与演进

身份与好友码有唯一索引；aliases 的 owner_id 与 alias_key 支持按本人备注索引。会话、限流及统计时间有相应索引。JSON 模型针对当前容量设计；扩容前宜改为按条目存储与分页。 结构变更先修改 db/schema.ts，再用 npm run db:generate 生成新增迁移并测试；生产启动只应用已有 SQL。

## 4 认证与请求安全

### 自托管账户与注册题

用户名为 3 至 32 位 ASCII 字母、数字、下划线、点或短横线，首位为字母或数字，按小写归一。新密码长度 12 至 128 字符且不超过 512 字节。密码使用独立随机盐和 scrypt 派生，参数 N=32768、r=8、p=3；比较使用定时安全比较。服务器不存明文密码。

注册前由服务端生成含加、减、乘、除和括号的算术题，保证整除和整数结果。GET /api/auth/challenge 返回题目、随机 challengeId 与过期时间；预期答案只在服务端核验。题目有效 5 分钟，一次有效格式的提交即消耗，答错也需换题，不能重复提交。此功能不接入第三方验证码，也不是强抗机器人屏障。

### 五次失败与三十分钟锁定

同一账户连续 5 次密码错误，锁定 30 分钟；锁定期间即使密码正确也不能登录。未到阈值的成功登录重置失败计数，锁定到期后可重新尝试。未知账户使用统一错误与限流，避免通过明显响应差异枚举账户。注册对新账号和已存在账号返回统一处理结果，之后由用户登录验证。

每次触发锁定，保留给系统的不可登录主体记录一笔轻微安全事件。事件不保存密码、会话令牌或私人正文，并排除好友关系与聚合。此记录用于安全审计，不作为普通用户的社交内容。强制锁定仍可能被恶意重复试错用来阻断他人登录，需配合入口限流。

### 会话与写入请求

- 会话令牌由 32 个随机字节生成；数据库只存 SHA-256 摘要，有效期 7 天。登出删除当前会话。生产 Cookie 为 HttpOnly、Secure、SameSite=Strict。
- 所有私有接口要求 X-Grudge-Owner 与当前用户匹配。修改请求另需正确 Origin、X-Grudge-Request: 1，并检查可用的 Sec-Fetch-Site。仅本机 HTTP 开发环境可关闭 Cookie Secure。
- 服务端使用参数化 SQL、请求体大小上限及持久化限流。浏览器私密 API 使用 no-store；日志不应记录 Cookie、密码或小本本内容。

Sites 模式使用平台身份，不运行应用内的密码注册、登录或找回。身份隔离由服务端认证结果决定，不能接受请求体中的任意 userId 作为所有者。

## 5 私密记录与旧数据导入

### 私人对象与真实账户分离

默认打开本机书库，不改写或预置旧数据；登录也不会自动上传或切换。账户书库须主动打开，账户正文与未保存草稿不进入浏览器持久存储。

记录中的 target 是主人给对象起的私人名称，可以是朋友、机构或物品。targetUserId 是独立的账户关联字段。只有双方已经互认、本人已给好友设置备注后，新建记录时才能从可搜索好友列表选择这个账户。重命名备注不会更换账户 ID；单纯手写相同名称不会形成关联。

从“关联好友并计入对方总数”的选择器选中好友，就是这笔新记录的明确计数选择，不再额外要求一个勾选框。自由文字记录保持私人记录。旧本、文件导入和演示记录不会按姓名补关联，也不能通过编辑旧记录追溯增加对方计数。计数提交立即持久化，对方看到的仍是延迟的周快照。

### 导入需要明确操作

1. 登录后检测浏览器原有本地数据，显示迁移说明；未经确认，不自动上传。先导出旧 JSON 是最稳妥的备份方式。
2. 解析、检查格式、数量、重复编号和字段长度。超过服务端容量时拒绝导入，不静默截断，也不覆盖云端当前内容。
3. 导入条目清除真实账户关联与统计参与标记。原有演示标签保留并排除统计，私人文本只进入当前账户；旧记录不得在导入后补关联。
4. 提交成功后仍保留原浏览器 localStorage。只有确认新账户内容完整、可导出且重新登录后仍在，才考虑自行清理旧数据。

### 并发与失败处理

整本保存携带当前 revision，只有收到服务器确认才更新“已保存”状态。版本冲突、网络结果不确定、会话过期或账号切换时暂停写入，待保存副本仅留在内存，可下载 JSON；重载需确认清除临时内容。不会自动重试并覆盖新版本。关闭页面可能丢失未下载的副本。

### 备份文件的边界

个人 JSON 用于记录与个人名册的迁移，不能恢复密码、登录会话或好友关系。另一部署的账户 ID 不代表同一身份。迁移后重新加好友并设置私人备注，只对之后新建的关联记录计数。备份可能含有敏感私人叙述，应保存在受保护的位置，不公开上传。

## 6 好友与聚合隐私

### 邀请与私人备注

好友码使用 128 位随机值，用户自行把代码交给要邀请的人。系统不提供用户名目录或全站搜索。请求必须由接收方接受后才成为好友；拒绝和解除关系均有独立状态变化。知道好友码仅允许发出请求，不直接建立关系。 好友与待处理请求合计上限为 500 位，备注最长 40 字符。

好友列表支持快速搜索定位。备注归设置者所有，用稳定账户 ID 绑定；同名备注不会合并账户。新建关联记录前必须已经互认并完成备注。旧记录、导入内容和示例不能靠相同名字自动成为关于某人的统计。

### 查看本人总数的资格

| 检查项 | 规则 |
| --- | --- |
| 本人记录 | 本人至少 5 条有效关联记录 |
| 好友人数 | 至少 10 位已经双方接受的好友 |
| 好友记录 | 上述至少 10 位好友各有至少 5 条有效关联记录 |
| 有效记录 | 显式选择互认且已备注的账户；非演示、非删除；满足服务端的新记录关联规则 |

“每人 5 条”指各自对合法互认好友账户的关联记录，不要求全部针对正在查看总数的人。总数只汇总本期符合条件的好友对本人的记录，不按严重程度加权；清账或原谅但未删除的记录仍可计数。接口不披露哪位好友达标或贡献几笔，也不提供好友的被记仇总数。

### 固定周快照

每周一 00:00 UTC 是固定边界，截止时间为此前 48 小时，即周六 00:00 UTC。成熟时间按服务端提交时间判断。每周首次查询生成并缓存快照，新增计数不会实时改变可见数字。撤回或解除好友会锁定受影响的本期，以及截止时间仍早于撤回的后续周期；待截止时间覆盖撤回后，再重新判断资格。解除好友还清除双方相关记录的计数选择并推进 revision，旧页面须重新加载。

### 仍然存在的风险

不验证邮箱、手机或真人身份，因此无法阻止一个人控制多个账号。串通、小样本、现实事件时间和已知关系仍可能让人猜出来源。周快照与门槛不是匿名证明；产品只承诺受限展示范围，不承诺无法推断身份。

## 7 API 与授权契约

接口同源并返回 JSON。私有接口必须携带与已验证当前账户一致的 X-Grudge-Owner，防止旧标签页串号；它不是登录凭据。修改请求另需正确 Origin 与 X-Grudge-Request: 1，有请求体时使用 application/json。接口不接受任意用户查询参数。

| 方法与路径 | 用途 | 权限或关键输入 |
| --- | --- | --- |
| GET /api/session | 部署模式和当前身份 | 可未登录 |
| GET /api/auth/challenge | 生成一次注册算术题 | 仅自托管；受限流 |
| POST /api/auth/register | 提交注册 | 仅自托管；用户名、密码、题目 ID 和答案 |
| POST /api/auth/login | 密码登录并发会话 | 仅自托管；受错误锁定与限流 |
| POST /api/auth/logout | 当前会话登出 | 仅自托管；已登录时也校验 X-Grudge-Owner |
| GET /api/notebook | 读取整本和 revision | 本人 |
| PUT /api/notebook | 保存整本 | 本人；expectedRevision、notebook |
| POST /api/notebook/import | 合并个人备份 | 本人；同上，清除导入关联 |
| GET /api/friends | 好友与待处理请求 | 本人；只返回自己的备注 |
| POST /api/friends/requests | 以随机码发请求 | 本人；friendCode |
| POST /api/friends/requests/{id}/accept 或 reject | 接受或拒绝请求 | 仅请求接收者 |
| PATCH /api/friends/{id} | 修改自己的好友备注 | 仅已接受关系；alias |
| DELETE /api/friends/{id} | 解除关系或取消请求 | 本人参与的关系 |
| GET /api/aggregate | 本人被记仇总数 | 通过门槛后返回周快照 |

### 错误处理

400 表示字段或关联规则错误；401 表示未登录或凭据无效；403 表示来源校验失败；409 表示 revision 冲突或页面持有的账号已变化；413 表示容量超限；429 表示限流。不能把错误后的本地界面变化当成已写入成功。汇总锁定时返回 locked，不泄露具体哪位好友差多少条。

## 8 部署与运行

### 独立服务器最小启动

需要 Node.js 24。运行时采用内置 HTTP、crypto 和 node:sqlite；数据库首次启动自动按顺序执行 drizzle 目录内 SQL，并在 __local_migrations 记录已应用版本。升级前先备份，已有 SQL 迁移不应原地修改。

```sh
cd grudge-book
PUBLIC_ORIGIN=http://localhost:3000 npm start
```

这条命令仅用于本机验证。生产环境必须设置实际 HTTPS 域名，TLS 在可信反向代理终止，并把后端绑定到仅代理可访问的地址。不要把本地 HTTP 测试配置直接公开。

| 配置 | 默认或作用 |
| --- | --- |
| PUBLIC_ORIGIN | 默认 http://localhost:3000；非本机必须 HTTPS |
| HOST 与 PORT | 默认 127.0.0.1 与 3000 |
| DATABASE_PATH | 默认 ./data/grudge.sqlite；必须持久化 |
| ENABLE_AGGREGATE | 设为 false 可关闭汇总读取 |
| TRUSTED_PROXY_IP | 可选；仅精确匹配该 TCP 对端时接受合法 X-Real-IP |

### 容器与发布

```sh
docker build -t grudge-book:2 .
docker run --rm -p 127.0.0.1:3000:3000 \
  -e PUBLIC_ORIGIN=https://your-domain.example \
  -e HOST=0.0.0.0 \
  -v grudge-data:/app/data grudge-book:2
```

示例域名需替换并配置 HTTPS 代理，持久化卷必须保留。默认按 TCP 对端限流；代理后可设置 TRUSTED_PROXY_IP 为唯一可信代理的准确地址，由代理覆盖 X-Real-IP。禁止把任意转发头当成真实来源，也不可让外部绕过代理直连。容器、卷权限和真实域名的 Cookie 行为需部署者验收。

### Sites 构建

```sh
npm ci
npm run build
```

构建把 public 静态资源与共用 API 打包为 Worker，并携带通用迁移与许可证。此源码不包含部署标识符或托管项目配置。部署者需自行提供可信平台身份入口、DB 绑定和供应商配置；不要直接把此 Worker 暴露在可伪造身份头的公网入口。独立部署请使用 Node 服务器。

## 9 迁移与备份恢复

### 从托管站迁到自己的服务器

1. 保留源站可用状态，下载完整源码并准备独立域名、HTTPS 入口与持久化存储。先在隔离环境验证安装和备份。
2. 在源站登录本人账户并导出个人 JSON。另存一份只读副本，核对条目数量、人物名册、废纸篓和特殊标记。
3. 启动自托管版，由每位用户自行创建用户名和密码。平台身份不携带可导出的应用密码，不应自动生成或分发用户凭据。
4. 在目标站登录后明确导入个人 JSON，重新建立互认好友关系并设置私人备注。导入的旧记录保持私密且不追溯计数；之后新建记录时再选择关联好友。
5. 对照原站检查数据、编辑、重新登录和再次导出。验证通过后再安排切换；保留旧站和离线备份，直到用户确认迁移完成。

以上是按用户迁移路径。完整 D1 数据搬迁到 SQLite 还涉及平台账户 ID 与本地账户的映射、密码初始化、关系重建和旧会话失效；本版不把 SQL 文件直接复制宣称为完整的跨认证系统迁移。不要让导入文件授予任何账户身份。

### 服务器备份与故障恢复

- SQLite：随源码附 server/backup.mjs，使用 online backup 生成一致副本且不覆盖已有目标。备份放在不同故障域，限制权限并加密；不要在持续写入时只复制主文件。
- D1：可使用供应商提供的备份、导出与 Time Travel 能力；具体保留期和可用性以账户当前配置为准。上线前实际演练，不把服务商能力当作已完成备份。
- 恢复演练：在隔离目录或数据库恢复，运行完整性检查和应用验证，再切换流量。记录恢复点与丢失数据时间窗口；过时会话应失效。

```sh
DATABASE_PATH=./data/grudge.sqlite \
  node server/backup.mjs /secure/path/backup.sqlite
```

### 无找回与灾备不是同一件事

服务器备份可恢复意外丢失的数据，不提供“忘记密码”功能。持有个人 JSON 也不证明有权进入某个账户。运维不应以任意改密码的方式绕过既定身份边界；如未来引入恢复流程，需单独设计与授权。

## 10 验收与维护清单

### 交付验收应覆盖的行为

| 领域 | 必须核对的结果 |
| --- | --- |
| 账户隔离 | A 不能读取或修改 B 的正文、备注或汇总 |
| 认证 | 注册题过期与重复提交失败；第 5 次错密锁定；锁定后正确密码仍失败；到期恢复 |
| 并发与导入 | 旧 revision 不覆盖新版本；重复导入不重复；旧本不被删除且不会追溯关联 |
| 好友与备注 | 请求需对方接受；只查自己的好友；改备注不改变绑定账户 |
| 聚合 | 本人 5 条且 10 位好友各 5 条；非示例且未删除；周快照有 48 小时截止 |
| 撤回与边界 | 退出计数或解除好友使相关当前快照锁定；不输出贡献者、正文或逐日变化 |

### 测试与上线状态

运行 npm run check 验证当前提交，测试覆盖真实 HTTP 与重启、前端 DOM 回归、认证、隐私并发、编译后的 Worker 与发布文件检查。持续集成对每个推送重新执行检查。Docker 构建运行、真实平台 D1、HTTPS 链路及完整交互浏览器验收仍须在目标部署中核验。

### 维护重点

- 限制数据库、卷与备份访问；配置空间、错误率和异常登录告警。同步检查密码哈希资源消耗，避免高并发注册压垮单进程。
- 容量上限是保护边界。长期使用时监控统计历史、过期会话和限流记录增长，制定归档与保留期，不无限堆积。
- 新依赖、Node 补丁、D1 行为和反向代理配置变化后，重跑账户隔离、导入与汇总测试，并至少定期演练一次恢复。
